1. PROJECT OVERVIEW
================================================================================

NetLinq is a native Android application for Quality of Experience (QoE) mobile
network monitoring in Cameroon. The app combines automatic network readings
(signal, speed, connection type) with user star ratings to capture how mobile
internet really feels on the ground.

Package name:        com.netlinq
Minimum Android:     8.0 (API 26)
Target / compile SDK: 35
Version:             1.0.0 (versionCode 1)
Language:            Kotlin
UI framework:        Jetpack Compose with Material 3
Backend:             Supabase (PostgreSQL, REST, Row Level Security)
Local storage:       Room Database (offline-first)
Background tasks:    WorkManager
Dependency injection: Hilt (Dagger)


================================================================================
2. IDENTITY AND ACCESS MODEL (OPTION 1 — CONFIRMED)
================================================================================

Decision: Anonymous subscriber model on mobile. No sign-up. No login. No email
or password. The SRS reference to "login/setup screens" is implemented as a
setup and onboarding flow only.

How attribution works without sign-up:
  - On first launch, a random UUID is generated and stored in DataStore.
  - All network metrics and feedback on that device link to this UUID locally.
  - Before Supabase upload, the UUID is hashed with SHA-256 → device_hash.
  - The cloud only sees device_hash, never the raw UUID or personal identity.
  - Same installation = same anonymous contributor in aggregated data.

Implications:
  - Reinstall or new phone = new anonymous contributor.
  - Personal dashboard shows this device's history from local Room.
  - Operators see trends across many device_hash values, not named individuals.

Aligns with: SRS FR1, Section 8.3, Implementation Decision Section 11.


================================================================================
3. ROLE-BASED ACCESS (FUTURE — NOT ON MOBILE)
================================================================================

Mobile app (NetLinq Android):
  - Subscribers only. Anonymous setup. No role selection at onboarding.
  - No admin or operator management on the phone in v1.
  - No operator analytics or debug tools in the consumer-facing UI.

Backend (Supabase) — future:
  - Roles (admin, operator) assigned by backend administrators only.
  - Users cannot self-promote.

Future desktop web dashboard — planned:
  - Admins: system maintenance, data integrity, role management.
  - Operators (e.g. MTN, Orange): aggregated analytics, trends, exports.
  - Authenticated web login separate from mobile anonymous flow.

Note: OperatorAnalyticsScreen.kt remains in the codebase as a coursework mock
for FR11 reference only. It is not reachable from the subscriber app UI.

4. TECHNOLOGY STACK AND UI IMPLEMENTATION APPROACH
================================================================================

Core Android:
  Kotlin 2.0.21, AGP 8.7.3, Java 17, KSP for Room and Hilt

UI layer:
  Jetpack Compose — entire UI is declarative; screen layouts in Kotlin
  Material 3 — components, color scheme, typography, bottom sheets, switches
  Navigation Compose — onboarding flow + main app tab navigation
  Material Icons Extended — cell tower, history, feedback, settings, etc.
  Compose Previews (@Preview) — design review without running on device
  Custom brand assets — cell tower logo (PNG) for launcher and onboarding

Architecture pattern (SRS Section 3):
  MVVM with Clean Architecture-style layers:
    Presentation — Compose screens, ViewModels, navigation, components
    Domain       — NetworkMetric, QoeFeedback, NetworkType, FeedbackNetworkLink
    Data         — Room, repositories, Supabase API, DataStore preferences
    Monitoring   — signal, speed, network type collectors, event detection
    Sync         — WorkManager periodic upload, 7-day purge

State management:
  ViewModels expose StateFlow / SharedFlow
  UI observes via collectAsState() in Compose
  User actions call ViewModel functions; UI remains stateless where possible

Edge-to-edge:
  MainActivity uses enableEdgeToEdge()
  statusBarsPadding() on onboarding and all main tab screens
  Status bar and navigation bar colours match theme background/surface
  Light/dark status and navigation bar icons adapt to selected theme

5. UI/UX DESIGN SYSTEM
================================================================================
(Full design rationale and user flows: docs/UI_UX_DESIGN_DOCUMENT.md)

5.1 Design principles
---------------------
  - Simple and self-explanatory: every screen has a title + short subtitle
  - Plain language for everyday users (not engineers):
      "Automatic readings" and "your ratings" — not objective/subjective/QoE
  - One primary action per area (Continue, Check now, Submit, Open dashboard)
  - Privacy communicated upfront — no account, anonymous ID explained
  - Feedback completable in under 30 seconds (quick prompt sheet)
  - Cards over flat lists for scannable information hierarchy
  - Quality communicated with colour and labels (Good/Fair/Poor, Strong/OK/Weak)
  - No debug or operator demo entry points in the subscriber UI
  - User-controlled appearance: System / Light / Dark in Settings

5.2 Typography (ui/theme/Type.kt)
----------------------------------
  Font family: System default (Roboto on most Android devices).

  Scale (NetLinqTypography):
    headlineLarge   32sp, Bold    — app title (onboarding)
    headlineMedium  26sp, Bold    — hero values ("4G", "Tap Check now below")
    titleLarge      20sp, SemiBold — screen section titles
    titleMedium     16sp, SemiBold — card titles
    bodyLarge       16sp, Normal   — intro copy
    bodyMedium      14sp, Normal   — descriptions
    labelLarge      14sp, Medium   — badges, step labels
    labelMedium     12sp, Medium   — captions, nav labels

5.4 Light and dark themes (ui/theme/Theme.kt + Settings)
--------------------------------------------------------
  Light mode:
    Background: Slate50, Surface: White
    Primary: TealDark, onPrimary: White

  Dark mode:
    Background: Slate900, Surface: Slate800
    Primary: TealLight, onPrimary: Slate900

  Theme selection (AppPreferences.themeMode):
    System default — follows phone setting (isSystemInDarkTheme)
    Light          — always light
    Dark           — always dark
  Choice saved in DataStore; applies immediately app-wide via MainViewModel.

5.5 Layout and spacing conventions
-----------------------------------
  Screen horizontal padding:     20–24 dp
  Top safe area:                 statusBarsPadding() on all main screens
  Vertical section spacing:      16–20 dp
  Card corner radius:            20 dp (NetLinqCard)
  Card elevation:                3 dp
  Hero card:                     subtle teal vertical gradient background
  Empty hero state:              centred content, larger icon, no placeholder badge
  Bottom nav:                    custom NetLinqBottomBar (4 tabs)
  Touch targets:                 Star ratings 36–40 dp; switches standard M3

5.6 Shared UI components (presentation/components/NetLinqComponents.kt)
------------------------------------------------------------------------
  NetLinqCard          Rounded elevated card container
  NetLinqBottomBar     Custom bottom nav — teal selected state, surface background
  SectionHeader        Title + optional subtitle block
  QualityBadge         Good / Fair / Poor coloured pill
  MetricStatChip       Compact value + label (Signal, Speed, Type)
  StarRatingBar        5-star row for quick feedback
  StarRatingRow        Labelled star row with description (feedback form)
  TrendChartPlaceholder Bar chart for speed trend
  StepIndicator        Horizontal progress bar for onboarding steps

5.7 Quality display logic (presentation/util/NetworkQuality.kt)
----------------------------------------------------------------
  Internal scoring uses dBm and ms; user-facing hero shows:
    Signal: Strong / OK / Weak (not raw dBm on main dashboard)
    Speed:  value in ms with "Speed" label (not "Latency")
    Overall badge: Good / Fair / Poor (worst of signal + speed)

5.8 Brand identity
------------------
  Logo: cell tower with signal waves (green/gold/teal) — Cameroon-relevant,
        professional, clear network meaning.
  Uses:
    - App launcher icon (adaptive icon, API 26+; mipmap fallbacks all densities)

8. DATA AND BACKEND
================================================================================

Room (offline-first) — database version 2:
  network_metrics
    signal, speed (latency_ms), type, device info, recorded_at, synced

  qoe_feedback
    five ratings, trigger_event, notes, recorded_at, synced
    network_metric_id      — links rating to exact reading row
    metric_recorded_at     — timestamp of linked reading
    signal_strength_snapshot, latency_ms_snapshot — copied at rating time

Feedback-to-network linking:
  - Event prompts carry metric ID + snapshot from reading that triggered them
  - Manual Feedback tab submit links to latest reading at submit time
  - Notification tap preserves metric data via intent extras
  - Sync payload includes linking fields for Supabase upload

Anonymous device ID:
  UUID in DataStore → SHA-256 hash as device_hash on upload

Supabase sync:
  Retrofit REST, WorkManager periodic sync (WiFi-only default, every 15 min)
  Manual Sync button on dashboard
  7-day purge of synced local records
  Credentials in local.properties (not committed)

Notifications:
  Local Android notifications (not remote FCM push)
  Shown when network event detected and app is in background
  Tap opens quick rating sheet with linked reading context
